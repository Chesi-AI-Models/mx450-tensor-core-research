# 阶段 3 · Falcon 安全模式判定的前置条件

## 一、已获得的确切信息

### Falcon 通用寄存器（`dev_falcon_v4.h`）

```
NV_PFALCON_FALCON_HWCFG     0x00000108   /* R--4R */
NV_PFALCON_FALCON_HWCFG2    0x000000f4   /* R--4R */
  HWCFG2.RISCV              bits 10:10
```

### SECURITY_MODEL 字段（`dev_falcon_v4.h`）

```
NV_PFALCON_FALCON_HWCFG1_SECURITY_MODEL   bits 5:4
  _NONE   = 0x0   (NS, 非安全)
  _LIGHT  = 0x2   (LS, 轻安全)
  _HEAVY  = 0x3   (HS, 重安全)
  _INIT   = 0x3   (初始值)
```

**只要读到 HWCFG1 的 bits 5:4，就能立刻判定 FECS/GPCCS 处于哪个安全模式。**

### FECS 控制寄存器区（nouveau `macros.fuc`）

```
NV_PGRAPH_FECS_INTR_ACK   0x409004
NV_PGRAPH_FECS_INTR       0x409008
NV_PGRAPH_FECS_ACCESS     0x409048
NV_PGRAPH_FECS_FIFO_DATA  0x409064
NV_PGRAPH_FECS_FIFO_CMD   0x409068
NV_PGRAPH_FECS_CAPS       0x409108
NV_PGRAPH_FECS_SIGNAL     0x409400
NV_PGRAPH_FECS_RED_SWITCH 0x409614
```

## 二、卡住的地方

**Falcon 实例基址未确定。**

矛盾点：
- 若 FECS 的 Falcon 基址 = `0x409000`，则 `HWCFG` 应在 `0x409000 + 0x108 = 0x409108`
- 但 `0x409108` 已被定义为 `NV_PGRAPH_FECS_CAPS`
- **两者冲突 → `0x409000` 不是 Falcon 基址**

说明 `0x409xxx` 是 **GR 引擎视角的 FECS 控制门面**，而 FECS 内部的 Falcon 核心寄存器
（HWCFG / CPUCTL / IMEMC 等）位于另一段基址。

## 四、为什么这一步值得做

**SECURITY_MODEL 决定后续所有可能性**：

| 读到的值 | 含义 | 后续 |
|---|---|---|
| 0x0 (NS) | 非安全模式 | **可以尝试读 IMEM**，可能拿到微码 |
| 0x2 (LS) | 轻安全模式 | 部分状态可见，仍有希望 |
| 0x3 (HS) | 重安全模式 | **host 完全不可见，此路终结** |

**一次寄存器读取，就能决定整条路是否还有意义。成本极低，信息量极大。**
