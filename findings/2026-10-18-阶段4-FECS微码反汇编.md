# 🔴🔴 阶段 4 · FECS 微码反汇编成功（11401 行 / 449 条寄存器写入）

**简体中文** | [繁體中文](2026-10-18-阶段4-FECS微码反汇编.zh-TW.md) | [English](2026-10-18-阶段4-FECS微码反汇编.en.md)

## 一、工具链打通

```
apt install cmake flex bison libxml2-dev libpciaccess-dev pkg-config g++
git clone --depth 1 https://github.com/envytools/envytools   (11 MB)
cmake -DDISABLE_HWTEST=ON -DDISABLE_NVA=ON -DDISABLE_VDPOW=ON .
make envydis -j4
```

**踩到的坑**：
1. `CMakeLists.txt` 第一行是 `project()`，第二行才是 `cmake_minimum_required` → 已改为 3.5
2. 只装了 gcc 没装 **g++** → CMake 报「compiler not found」，装 g++ 后通过
3. envydis 输出带 **ANSI 颜色码**，需加 `-n` 禁用，否则正则全不匹配

**最终命令**：
```bash
envydis -m falcon -V fuc6 -i -n fecs_imem.bin > fecs_plain.asm
```

## 二、反汇编结果

**11401 行，1.3 MB**，`-V fuc6` 与 `core_rev=6` 完全对应。

### 入口（0x0）

```asm
00000000: mov $r0 0x2000        ; 栈顶 0x2000
00000005: mov $sp $r0           ; 设置栈指针
00000008: clear b32 $r10
0000000a: lcall 0x6ca0          ; 调用 main（位于 0x6ca0）
0000000e: exit                  ; 返回即停机
```

**与社区对 AD102 的分析结构完全同构**（AD102: 栈顶 0x2800 → `lcall 0x7747` → 停机），
差异仅来自世代不同（DMEM 大小、函数布局）。

### main 位于 0x6ca0（第 9115 行）

```asm
00006ca0: f9 52              C  mpush $r5
```

## 四、样例代码（写 0x20600 系列）

```asm
00000076: mov $r9 0x20600          ; 目标寄存器
0000007a: extr $r10 $r14 0x3:0x3   ; 取位段
0000007d: iowr I[$r9] $r15         ; 写入
00000080: iowr I[$r9] $r14         ; 再写
00000083: bra b32 $r10 0x0 ne 0x8c
00000087: mov $r15 0x2
00000089: iowr I[$r9] $r15         ; 条件写入
0000008c: ret
```

这是典型的「配置寄存器 + 条件分支」模式。

## 五、下一步

1. **确认 `0x20000` 段归属**：
   - 查 envytools `rnndb/` 或 nouveau 的 `NV_PGRAPH_*` / `NV_PGPC_*` 定义
   - 判断是否为 GPC/SM 级配置（若是，则与 TC 强相关）
2. **定位 TC 相关写入**：
   - 在 0x20000 段的 379 次写入中，找「成组配置」模式
   - 结合 SM 数量（14 个）判断是否有按 SM 循环的初始化序列
3. **dump GPCCS 微码**：
   - GPCCS 直接管 GPC 内的 SM，TC 配置更可能在此
   - 需另找 GPCCS 的 Falcon 基址
