# 階段 3 · 32MB 顯示記憶體 dump 分析：Falcon 微碼不在此處

## 一、分析方法

用 gk20a（Kepler）微碼作參考提取特徵：

```
fecs_inst.bin : d0 00 10 00 00 fe 04 00 bd a4 7e 2f 3a 00 f8 02
gpccs_inst.bin: d0 00 08 00 00 fe 04 00 bd a4 7e d9 1e 00 f8 02
                    ↑     ↑^^^^^^^^^^^^^^^^^
                堆疊頂端   12 位元組共同前綴
```

cracker 社群對 AD102（Ada）FECS 的逆向筆記也確認：入口 0x0 是「堆疊頂端 + `lcall main`」，
反組譯用 `envydis -m falcon -V fuc6`。

## 二、掃描結果

| 檢測項 | 結果 |
|---|---|
| 強特徵 `00 fe 04 00 bd a4 7e`（8 位元組） | **0 處** |
| 放寬 `d0 00 ?? 00` | 215 處，但上下文均為資料表（如 `d0 00 d1 00 d2 00 d3 00`） |
| 高熵 4KB 區塊（非零率 > 80%） | 6457 / 8192 |

**結論：32MB dump 中不存在 Kepler 風格的 Falcon 微碼。**

## 三、原因（有明確文獻依據）

> "Falcons have **separate instruction and data memories (IMEM/DMEM)** and provide a small
> DMA engine (via the FBIF - 'Frame Buffer Interface') to load code from system memory."
> —— kernel.org `gpu/nova/core/falcon.html`

**Falcon 微碼被載入 Falcon 自己的 IMEM（內部 SRAM），不在 VRAM。**

我們 dump 的 32MB 是 **GSP 的執行時資料區**（含韌體副本、堆、表結構），
不是微碼存放區。

## 四、讀取 IMEM 的障礙

> "**Heavy Secure (HS)**: In this mode, the microprocessor is a **black box** — it's not
> possible to read or write any Falcon internal state or Falcon registers from outside
> the Falcon (for example, from the host system)."
> —— NVIDIA `Falcon-Security` 公開文件

安全模式分級：

| 模式 | 誰能載入 | host 能否讀寫內部狀態 |
|---|---|---|
| NS (PL0) | 不需要簽章 | 可以（但能力受限） |
| LS (PL2) | 需 HS ucode 載入 | 部分可見（便於除錯） |
| **HS (PL3)** | **需 NVIDIA 簽章** | **完全不可見** |

啟動鏈（Ampere/Turing 同構）：

```
硬體 BROM → HS ucode (Booter, 在 SEC2) → LS ucode (GSP-RM, 在 GSP)
```

而 FECS/GPCCS 由 **HS 的 FWSEC / devinit** 載入，很可能執行在 LS 或 HS 模式。
若為 HS，則 IMEM 對 host 完全不可讀。

## 五、目前掌握的完整事實鏈

| # | 事實 | 依據 |
|---|---|---|
| 1 | TC 指令存在，吞吐被壓到理論值 5% | SASS + 三路徑實測 |
| 2 | GSP 韌體是雙層 RISC-V ELF，不含 TC 控制邏輯 | 完整反組譯 |
| 3 | Ampere 的 PLM/SS0/SS1 機制在 Turing 韌體中不存在 | 8 位址零命中 |
| 4 | vBIOS 受 FWSEC 憑證鏈驗證 | 韌體內錯誤碼列舉 |
| 5 | **可以在驅動執行時透過 PRAMIN 讀寫顯示記憶體** | 寫-讀回 CHANNEL WORKS |
| 6 | **顯示記憶體中不含 Falcon 微碼** | 本次 32MB dump 分析 |
| 7 | Falcon 微碼在 IMEM；HS 模式下 host 不可讀 | NVIDIA 公開文件 |

## 六、下一步（唯一剩餘方向）

**嘗試透過 Falcon 暫存器存取 IMEM**：

1. 在 BAR0 中定位 FECS / GPCCS 的 Falcon 暫存器基底
   （envytools 文件有 Falcon 暫存器佈局，但 Turing 的實例偏移需確認）
2. 讀 Falcon 的 `CPUCTL` / `HWCFG` 暫存器，判斷目前安全模式
3. 若為 NS/LS → 可嘗試讀 IMEM（透過 `FALCON_IMEMC/IMEMD` 或 `DMEMC/DMEMD`）
4. 若為 HS → 此路不通，只能等 NVIDIA 公開資料或硬體層手段

**前置檢查**：讀 `NV_PFALCON_..._HWCFG` 的 `SECURITY_MODE` 欄位即可判定，成本很低。
