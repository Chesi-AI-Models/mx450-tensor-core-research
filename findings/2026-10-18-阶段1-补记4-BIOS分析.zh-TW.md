# 2026-10-18 · 階段 1 補記 4：系統 BIOS dump 與 vBIOS 定位（C 路線，判定不可行）

## 動作

1. 檢查 ACPI 表：無 `VFCT`（筆電 GPU vBIOS 常見的 ACPI 載體）
2. 安裝 `flashrom` + `acpica-tools`
3. 探測 SPI Flash 控制器
4. 唯讀匯出 BIOS 區域
5. 在 dump 中定位 NVIDIA vBIOS

## 1. ACPI 表檢查

可用表：`APIC BGRT DBG2 DBGP DMAR DSDT FACP FACS FPDT HPET LPIT MCFG MSDM NHLT PTDT
SSDT1-20 TPM2 UEFI WSMT`

**沒有 `VFCT`**（Virtual Function Control Table）。該類表通常用於向系統提供
獨立顯示卡的 vBIOS 副本；缺失意味著這條路不存在。

## 2. SPI Flash 探測

```
Found chipset "Intel Tiger Lake U Premium".
FREG0: Flash Descriptor region (0x00000000-0x00000fff) is read-only.
FREG1: BIOS region (0x00800000-0x017fffff) is read-write.
FREG2: Management Engine region (0x00001000-0x007fffff) is read-only.
SPI Configuration is locked down.
Enabling hardware sequencing due to multiple flash chips detected.
```

- 整片 Flash 24576 KB（24 MB）
- BIOS 區域：`0x00800000 – 0x017FFFFF`（16 MB）
- ME 區域唯讀，BIOS 區域標稱可寫但受 PR0–PR3 保護

## 3. 唯讀匯出

```bash
flashrom -p internal:laptop=force_I_want_a_brick --ifd -i bios \
         -r /vol1/ganlin/bios/bios_readonly.bin
```

結果：`25165824` 位元組（24 MB），MD5 `4d2c99e85e761e0a3b1b8dcada4cc950`
（`--ifd -i bios` 未生效，實際讀出整片 Flash，含 Descriptor + ME + BIOS）

> 註：全程僅使用 `-r` 唯讀參數，未執行任何抹除／寫入。

## 4. vBIOS 定位結果

| 檢測項 | 結果 |
|---|---|
| 標準 PCI Option ROM（55AA + PCIR，VID=0x10DE） | **0 個** |
| 字串 `NVIDIA` | **0 處** |
| 字串 `90.17.64`（nvidia-smi 回報的 VBIOS 版本） | **0 處** |
| 字串 `TU117` | **0 處** |
| `_FVH`（UEFI 韌體卷簽章） | 僅 `0x01400000` 一處 512 KB |
| `LZMA` / `Tiano` / `EFI_COMPRESS` | 全為 0 |

`0x00800000` 起始內容為：

```
02 0F 3E 90 10 2D E0 44 90 EE E7 EF F0 A3 ED F0
```

**非 `_FVH`、無可辨識壓縮頭 —— 是密文。**

## 5. 判定

**BIOS 主體受 Intel Boot Guard 保護並加密，靜態 dump 無法提取 vBIOS。**

Boot Guard 的信任鏈起點在 CPU 熔絲內的公鑰，BIOS 關鍵區域（IBB）以簽章+加密方式儲存，
只有經過 ROM 階段驗證後才在執行時解密到記憶體。**沒有廠商私鑰，靜態解析不可能。**

同時印證了另一件事：驅動卸載後 PCI ROM BAR 回傳 `EIO`（零位元組），
說明 GPU 自身沒有 ROM，BIOS 也沒有透過 PCI 機制提供明文 Option ROM ——
`nvidia-smi` 回報的 `VBIOS Version: 90.17.64.00.14` 很可能是驅動從 GPU 內部
某個資訊結構讀取的版本號，而非完整 vBIOS 映像。

## 結論

**C 路線不可行。** 三條高層路徑至此全部探底：

| 路線 | 手段 | 結果 |
|---|---|---|
| A | CUPTI metric 列舉 | `rc=38`，零 metric；開權限後不變 |
| B | `NV2080_CTRL` ioctl | 通道打通（ROOT_CLIENT 成功），`GR_GET_INFO` status=31 |
| C | 系統 BIOS / vBIOS 靜態分析 | Boot Guard 加密，無法提取 |

## 這三條路共同說明什麼

這台機器的韌體與驅動堆疊在**三個層次上同時設防**：

1. **硬體層**：GPU 無獨立 SPI Flash，vBIOS 不由自身提供
2. **韌體層**：系統 BIOS 受 Intel Boot Guard 簽章加密，無法靜態解析
3. **驅動層**：使用者態 API（NVML / CUPTI / 私有 ioctl）對關鍵能力做了裁剪或物件級隔離

**這不是「技術難度高」，是「設計上逐層封死」。**

## 還沒被排除的路徑（供後續參考）

| 路徑 | 前提 | 可行性 |
|---|---|---|
| 執行時攔截 GSP 載入 | 編譯 `nvidia-open` 核心模組 + 找 Turing 的 Falcon 載入點 | 技術可行，但**目標暫存器位址未知**（開源標頭檔中無 PLM/CFG1 定義） |
| 從記憶體中抓取已解密的 vBIOS | 在 BIOS POST 後、驅動載入前 dump 實體記憶體 | 需要自訂核心模組或 kdump，且 Boot Guard 會清理 |
| 硬體層量測 | 邏輯分析儀／示波器觀察 TC 時鐘域 | 需要拆機與專業設備 |
