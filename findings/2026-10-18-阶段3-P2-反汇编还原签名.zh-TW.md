## 還原的函式原型

```c
void *os_map_kernel_space(void *addr, NvU64 size, NvU32 cache_type)
{
    if (!addr) {
        if (cache_type == 0)
            return <全域物件>;              /* 0x...3bd2 讀的全域 */
        ...
    }

    /* 不允許在中斷上下文中對映 */
    if (!(read_flags() & IF) || preempt_count())
        return <錯誤路徑>;

    switch (cache_type) {
    case 0: return map_uncached(addr, size);   /* 尾呼叫 0xffffffffb04a4730 */
    case 2: return map_cached(...);
    case 6: return map_xxx(...);
    default:
        log(4, "invalid cache type");
        return NULL;
    }
}
```

**與 nvidia-open 原始碼中的 `os_map_kernel_space(virtAddr, size, cache_type)` 原型一致。**

## 當時已知的 cache_type 三個取值

| 值 | 推測語意 | 依據 |
|---|---|---|
| 0 | UNCACHED / 快速路徑 | `cmp $0x2` 前先 `test edx,edx`，等於 0 走尾呼叫 |
| 2 | CACHED | 顯式 `cmp $0x2` 分支 |
| 6 | WRITE_COMBINED 類 | `cmp $0x6` 分支 |
| 其他 | 無效，記錄日誌回傳 NULL | 預設分支 |

## 意義

1. **完整還原了一個 NVIDIA 核心函式的行為**——不是從文件抄，是從機器碼讀出來的
2. 拿到了呼叫它所需的全部參數語意
3. 這是 P3「讀取 FECS/GPCCS 微碼」的**必要工具**：要讀 GPU 內部 SRAM，必須先能對映位址

## 但這不是「鎖」

`os_map_kernel_space` 是**開門用的鑰匙**，不是鎖本身。

- 它能讓我們把實體位址對映到核心可存取的虛擬位址
- 有了它，才能讀 GPU 裡的東西（顯示記憶體、Falcon SRAM、微碼）
- **真正的「鎖」在 FECS/GPCCS 微碼和硬體配置裡**（見 findings 階段2）
