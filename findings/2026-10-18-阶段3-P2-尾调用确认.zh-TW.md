# P2 第三階段：尾呼叫確認與完整函式集

## 一、連網核查結果（本節修正先前兩項推斷）

### 核查 1 · 函式原型（已確認）

DeepWiki 對 `os-interface.c` 的解讀：

```
Kernel Space Mapping — os_map_kernel_space() 依 cache 屬性對映實體記憶體
  Cached         NV_MEMORY_CACHED          nv_ioremap_cache()
  Write-Combined NV_MEMORY_WRITECOMBINED   nv_ioremap_wc() / nv_ioremap_nocache()
  Uncached       NV_MEMORY_UNCACHED        nv_ioremap_nocache()
  Default        NV_MEMORY_DEFAULT         nv_ioremap_nocache()
```

### 核查 2 · **先前的參數數量推斷有誤：實際是 4 個參數**

`src/nvidia/arch/nvalloc/unix/src/osapi.c` 中的真實呼叫：

```c
reg_mapping = osMapKernelSpace(nv->regs->cpu_address,   /* 實體位址 */
                               os_page_size,             /* 大小 */
                               NV_MEMORY_UNCACHED,       /* cache_type */
                               NV_PROTECT_READABLE);     /* protect */
```

**四個參數**。而我反組譯的 `os_map_kernel_space` 只看到 `rdi`/`rsi`/`edx` 三個
（未見 `ecx` 的使用），說明：

- `osMapKernelSpace`（4 參數）是 public API 層
- `os_map_kernel_space`（3 參數）是其下層核心實作
- 我讀的是後者，**簽章需按 3 參數理解，protect 在更上層處理**

## 二、尾呼叫目標已確認

`os_map_kernel_space` 中 `cache_type == 0` 分支尾呼叫 `0xffffffffb04a4730`：

```
$ grep -E "^ffffffffb04a47" /proc/kallsyms
ffffffffb04a4700 T ioremap_encrypted
ffffffffb04a4720 T __pfx_ioremap_cache
ffffffffb04a4730 T ioremap_cache          ← 目標
ffffffffb04a4750 T __pfx_ioremap_prot
ffffffffb04a4760 T ioremap_prot
```

**結論：`os_map_kernel_space` 是對核心 `ioremap` 系列的薄封裝。**
這與 NVIDIA 開源程式碼的結構完全吻合。

## 三、⚠ 未解的矛盾（呼叫前必須澄清）

反組譯顯示 **`cache_type == 0` → `ioremap_cache`**。

但 NVIDIA 慣例是 `NV_MEMORY_UNCACHED = 0`，若如此則應呼叫 `ioremap_uc` / `ioremap_nocache`。

**二者必有一錯**，可能原因：

| 假設 | 說明 | 驗證方法 |
|---|---|---|
| A. 列舉值並非 UNCACHED=0 | 該版本 `NV_MEMORY_*` 數值與我記憶不同 | 從 580.142 的 `nvtypes.h` 讀取真實列舉 |
| B. 讀取起點偏移 | 0x...bc0 可能是某個 thunk 而非真入口 | 對比 `__pfx_`（+0x10）與本體 |
| C. `ioremap_cache` 語意差異 | 6.x 核心中該函式行為改變 | 查核心原始碼 `arch/x86/mm/ioremap.c` |
| D. 該分支不是 cache_type 分派 | 我誤讀了 edx 的用途 | 逐條核對指令語意 |

**在澄清之前不得呼叫該函式** —— 用錯 cache 屬性對映 GPU 記憶體可能導致一致性錯誤、
資料損壞，甚至 GPU 掛起。

## 五、`nv_al_*` 系列不存在

`grep -oE "nv_al_[a-z_]+" /proc/kallsyms` → **零結果**。

說明 `nv_al_add_mapping` 這類函式名不正確，或被內聯／改名為其他形式。
位址空間管理走的是 `os_*` 抽象層，不是 `nv_al_*`。
