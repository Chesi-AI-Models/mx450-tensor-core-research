
**`00 fe 04 00 bd a4 7e` 完全匹配**，第 3 字节（栈顶值 0x10 vs 0x20）和后续地址不同属正常
（不同世代的 DMEM 大小与函数布局不同）。

**结论：这是真正的 FECS Falcon 微码，不是噪声。**

## 三、成功的关键条件（缺一不可）

| 条件 | 为什么必须 |
|---|---|
| **内核模块 ioremap BAR0** | 用户态 mmap 会 EBUSY（驱动占用） |
| **驱动必须加载** | 卸载驱动 → Falcon reset → IMEM 清空（实测全 0） |
| **GPU 必须满载** | 空闲时 FECS `halted=1`，IMEM 内容不可访问（实测全 0） |
| **FECS 在 LS 模式** | 若为 HS（black box），host 完全不可读 |
| **IMEMC 地址换算正确** | `(blk<<8) \| (word<<2)`，`blk=addr/256` |

**这五个条件同时满足，才拿到这 32KB。**

## 四、读取流程（可复现）

```c
// 1. GPU 满载（torch 跑 GEMM 循环）
// 2. insmod mx450_p4.ko bar0_phys=0x5f000000 mode=dump dump_bytes=32768
// 3. 模块内部：
//    ioremap(BAR0 + 0x409000, 0x1000)
//    读 HWCFG1 确认 security_model == 2 (LS)
//    保存 IMEMC(0) 原值
//    for (addr = 0; addr < 32768; addr += 4) {
//        blk  = addr / 256;
//        word = (addr % 256) / 4;
//        writel((blk<<8)|(word<<2), base + 0x180);
//        *(u32*)(buf+addr) = readl(base + 0x184);
//    }
//    恢复 IMEMC(0)
//    kernel_write 到文件
```

## 五、这为什么是重大突破

**公开资料里，消费级 GeForce（尤其笔记本 MX 系列）上从未有 Turing FECS 微码被 dump 的记录。**

原因是一连串"被认为不可能"的限制：

| 限制 | 常规认知 | 本次如何绕过 |
|---|---|---|
| BAR1 只映射 16MB | 读不到显存 | 改走 PRAMIN（BAR0+0x700000） |
| P2P API 对 GeForce EINVAL | 无法 pin VRAM | 不走 P2P |
| 驱动运行时 BAR0 被占用 | 无法访问寄存器 | 内核模块 ioremap |
| Falcon 若为 HS 则黑箱 | 完全不可读 | **实测为 LS**（关键） |
| 空闲时 Falcon halted | IMEM 不可访问 | **制造 GPU 满载** |

**五道锁，逐一打开。**
