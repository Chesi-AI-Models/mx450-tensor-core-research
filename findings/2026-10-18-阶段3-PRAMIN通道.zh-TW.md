# 2026-10-18 · 階段 3：PRAMIN 通道發現與首次驗證

## 一、連網核查（每步一搜的結果）

### 核查 1 · BAR1 為什麼全零（真實原因）

> "The GPU's internal page tables only have **~16 MiB of BAR1 mapped (just the display
> framebuffer)**. Reads from the rest return zeros."
> —— nbd-vram 專案分析

**並非 D3cold，而是 GPU 內部頁表只對映了 16MB 畫面緩衝區。** 先前「喚醒 GPU 再讀」的假設不成立。

### 核查 2 · P2P 通道對消費級卡關閉

> "`nvidia_p2p_get_pages_persistent`... **the NVIDIA driver returns EINVAL on consumer
> GeForce GPUs**. Both persistent and non-persistent variants, both flag values.
> It's gated at the RM level for Quadro/datacenter SKUs only, regardless of driver version."

### 核查 3 · PRAMIN 通道存在且官方在用

NVIDIA 新的 Rust 驅動 **nova-core** 中：

```rust
const PRAMIN_BASE: usize = 0x700000; // PRAMIN is always at BAR0 + 0x700000
const PRAMIN_SIZE: usize = 0x100000; // 1MB aperture
```

官方文件（[PATCH 09/12] docs: gpu: nova-core）：

```
PRAMIN Window Operation
=======================
1 MiB sliding aperture, repositioned over the entire VRAM address space
using NV_PBUS_BAR0_WINDOW register (0x1700):

 31:26 | 25:24  | 23:0
 RSVD  | TARGET | BASE_ADDR (bits 39:16 of VRAM address)

TARGET: 0x0 = VRAM, 0x1 = SYS_MEM_COH, 0x2 = SYS_MEM_NONCOH

actual_vram_addr = (BASE_ADDR << 16) + pramin_offset
```

本機 `open-gpu-kernel-modules` 標頭檔同樣確認：
`NV_PRAMIN 0x007FFFFF:0x00700000 /* RW--M */`（Maxwell 至 Blackwell 均有）。

## 二、本機實測 1 · 視窗可讀

```
[NV_PBUS_BAR0_WINDOW @0x1700] = 0x00007FF0
  TARGET    = 0  (VRAM)
  BASE_ADDR = 0x007FF0
  => 視窗目前覆蓋 VRAM 0x007FF00000（2GB 顯示記憶體末尾）
```

**PRAMIN 機制在本機確認存在，暫存器可讀。**

## 三、本機實測 2 · 視窗可寫，但讀回全零

掃描前 256MB（每 1MB 取樣 4KB）：

```
有資料的區域: 0 / 256
WINDOW 已還原為 0x00007FF0
```

- 寫 `0x1700` 無報錯（視窗移動成功）
- 但所有視窗讀回全零
- 讀完後已還原原視窗值，驅動正常重新載入

## 四、關鍵判斷：全零是測試條件造成的

**本次測試卸載了 nvidia 驅動**（否則 BAR0 被佔用，無法 mmap）。

驅動卸載時 NVIDIA 會清理顯示記憶體（安全策略），因此整片顯示記憶體本就為零 ——
這與 PRAMIN 機制是否有效無關。

**同時這也解釋了 BAR1 全零的另一層原因**：不只是頁表對映只有 16MB，
卸載驅動後顯示記憶體內容本身也已被清空。

## 五、結論：必須在驅動執行時存取

| 條件 | BAR0 mmap（使用者態） | 核心模組 ioremap |
|---|---|---|
| 驅動執行中 | ❌ 被佔用，EBUSY | ✅ 可對映 |
| 驅動卸載後 | ✅ 可對映 | ✅ 可對映 |
| 顯示記憶體內容 | ❌ 已清空 | ✅ 保留 |

**唯一可行路徑：寫核心模組，在驅動執行時 `ioremap` BAR0 的 0x700000 區域，
用 PRAMIN 視窗讀顯示記憶體。**

## 六、下一步

1. 模組透過 `module_param` 接收 BAR0 實體位址（從 `/sys/bus/pci/devices/*/resource` 讀取）
2. 模組內 `ioremap(BAR0 + 0x700000, 0x100000)` 對映 PRAMIN 視窗
3. 另需 `ioremap(BAR0 + 0x1700, 4)` 讀寫視窗暫存器
4. 保持 nvidia 驅動載入（GPU 有電、顯示記憶體有內容）
5. 移動視窗掃描顯示記憶體，尋找 FECS/GPCCS 微碼特徵

**風險**：與驅動並行存取 BAR0 暫存器可能衝突。需要：
- 只讀為主
- 每次讀後還原視窗原值
- 避免在驅動正在操作 PFB/PBUS 時存取

- WINDOW 暫存器已還原原值 `0x00007FF0`
