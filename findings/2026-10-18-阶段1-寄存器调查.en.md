> Environment: LYLNAS / fnOS (Debian 12) / kernel 6.18.18 / driver 580.142 / MX450 `10de:1f97`

## 1. Actions this round

1. `gh` search of `NVIDIA/open-gpu-kernel-modules` (the Turing+ open kernel modules)
2. fetch the register headers under `src/common/inc/swref/published/turing/tu102/`
3. search each of them for fuse / FBPA / GSP / PLM / TENSOR definitions

## 3. Key findings

### Finding 1 · `dev_fuse.h` contains no Tensor Core related fuse at all

The whole file has just two entries:

```c
#define NV_FUSE_OPT_SECURE_GSP_DEBUG_DIS   0x0002174C  /* RW-4R */
#define NV_FUSE_OPT_NVDEC_DISABLE          0x00021378  /* RW-4R */
```

- the permission tag `RW-4R` = read/write, 32-bit — **fuse registers are accessible at the driver level**, not a
  complete black box
- **but there is no TC capability bit.** If TCs were fused off via OTP, there should in theory be a definition like
  `NV_FUSE_OPT_TENSOR_DISABLE`

**Inference**: TU117's TC throttling **is very likely not implemented through fuses**. This weakens hypothesis A
("physical fuse-off"), but at the same time gives no address for hypothesis B ("register-writable").

### Finding 2 · Turing's FBPA header has no CFG1

What `cmpunlocker` modifies on GA100 is:

```
FBPA_CFG1 (0x009A0204) = 0x02779000   # 64GB HBM2e geometry
```

whereas the whole of `tu102/dev_fbpa.h` is just:

```c
#define NV_PFB_FBPA_0_ECC_DED_COUNT(i)  (0x00900488+(i)*4)  /* RW-4A */
```

- the address prefix `0x00900xxx` is a different segment from GA100's `0x009A0xxx`
- **no CFG1 / PLM definitions**

**Inference**: VRAM geometry configuration is outside what the open headers publish. For the MX450 this is
irrelevant (its VRAM is a physically soldered 2 GB), but it shows that **"copy CMPUnlocker's address table
verbatim" does not hold on Turing**.

### Finding 3 · PLM cannot be found anywhere under the Turing directory

`gh search code "PLM" --repo NVIDIA/open-gpu-kernel-modules` returns **zero hits** on the Turing path.

The core of CMPUnlocker is opening four PLM registers (`FEAT_PLM` / `FBPA_PLM` / `WPR_PLM` / `WPR_CFG`),
and Turing's open sources contain none of it.

**Inference**: either Turing uses a different mechanism for privilege isolation, or this whole part lives inside the
closed-source GSP microcode. In either case, **CMPUnlocker's injection target addresses are unusable on Turing**.

### Finding 4 · `dev_gsp.h` exposes the Falcon communication interface

```c
#define NV_PGSP                         0x113fff:0x110000
#define NV_PGSP_FALCON_MAILBOX0         0x110040   /* RW-4R */
#define NV_PGSP_FALCON_MAILBOX1         0x110044   /* RW-4R */
#define NV_PGSP_QUEUE_HEAD(i)           (0x110c00+(i)*8)
#define NV_PGSP_QUEUE_TAIL(i)           (0x110c04+(i)*8)
#define NV_PGSP_EMEMC(i)                (0x110ac0+(i)*8)
#define NV_PGSP_EMEMD(i)                (0x110ac4+(i)*8)
```

**This is the most valuable gain of the round.** Turing is the first NVIDIA generation to introduce the GSP;
the GSP firmware communicates with the host through this mailbox/queue set and has a direct channel to EMEM
(external memory).

`cmpunlocker`'s principle is precisely to **tamper with the signature section before GSP-RM starts**, hijacking the
execution flow. The same `PGSP` interface set exists on the MX450 — **an injection entry point physically exists**.

### Finding 5 · the driver has a control command to query the TC count (unused)

```c
#define NV0080_CTRL_GR_INFO_INDEX_TENSOR_CORE_COUNT   (0x00000023)
// "This index is used to return the number of Tensor Cores"
```

This shows the GR engine knows how many TCs this chip has. If that value could be read:

- reporting 56 (14 SM × 4) → TCs are acknowledged by hardware and merely throttled → **hypothesis B holds**
- reporting 0 → TCs are already considered unavailable at the driver level → **close to A/D**

Reading it requires the `NV2080_CTRL` ioctl (an NVML private interface); not implemented this round.
**This is the highest-priority action for the next round** — it is direct evidence for the nature of the lock.

## 4. Conclusions this round

| Hypothesis | Evidence this round | Judgement |
|---|---|---|
| A. OTP eFuse fuse-off | no TC bit in the fuse header | **weakened** (but may be unpublished) |
| B. register-level throttle | no Turing SS/PLM definition found | **pending verification** (needs the TC count) |
| C. devinit table configuration | requires a system BIOS dump | not started |
| D. hardware designed at low rate | NVIDIA forums say "throttled throughput" | **still possible** |

**Net gains**: confirmed that CMPUnlocker's register address table **cannot be copied** (Turing's namespace differs),
but also confirmed that **a GSP Falcon injection channel exists** (`NV_PGSP`), which provides the only feasible entry
point for later work.
