## 2. Five confirmed core facts

1. **TCs exist but are throttled**: hand-written PTX mma 0.60 TFLOPS vs theoretical 6–12; the cuBLAS TENSOR_OP path
   is 0.32 (6.4× slower than FP32)
2. **GSP firmware contains no TC control logic**: after fully disassembling the dual-layer RISC-V ELF, 8 Ampere
   register addresses were zero-hit
3. **PRAMIN channel usable**: read/write VRAM via BAR0+0x700000 while the driver runs; write-readback verified
4. **FECS is in LIGHT SECURE mode**: HWCFG1 = 0x80104126 → core_rev=6 (fuc6), security_model=2 (LS)
5. **FECS microcode fully readable**: at full GPU load IMEM is accessible; all 32 KB on disk

## 3. The blocker: the ownership of the 0x20000 segment is undetermined

**Of the microcode's 449 `iowr` instructions, 379 fall in `0x20000-0x2FFFF`**, with addresses stepping regularly.

Investigation results:

| Source | Conclusion |
|---|---|
| envytools `rnndb/nv_mmio.xml` | `0x400000-0x5FFFFF` = PGRAPH; `0x20000-0x227FF` = PTHERM/PFUSE/PUNITS |
| what the microcode actually accesses | includes `0x22a00 / 0x23200 / 0x23300 / 0x23800`, **beyond envytools' 0x227FF upper bound** |
| the `turing/tu102/` header directory | **has no `dev_gpc.h` / `dev_tpc.h`** |

**Conclusion: Turing's GPC/TPC register definitions are not provided in any public header; envytools' mapping stops
at Maxwell.**

## 4. Three routes for tomorrow (entry points already validated as feasible)

### Route 1 · reverse from the HAL sources (recommended, lowest cost)
`src/nvidia/src/kernel/gpu/gr/` contains HAL implementations per generation (`kern_gr_tu102.c` etc.),
which reference the GPC/TPC register offset constants. `gh search code "NV_PGRAPH_GPC"` can locate them.

### Route 2 · find loop patterns in the disassembly (no external material needed)
If the write sequence near `0x21800` shows **14 iterations** (the MX450 has 14 SMs),
that alone establishes it as an SM-level configuration loop — the structure is understandable without knowing the
register names.

### Route 3 · compare against the AD102 FECS analysis
If the Kanxue article (all 9797 instructions annotated) also accesses the `0x2000x` segment,
this is a cross-generation unified layout, and its naming and annotations for 109 functions can be borrowed directly.

## 5. One bottom line that must be remembered

**The microcode can be read, not modified.**

- `FWSEC` performs certificate-chain verification on the microcode (8 `VERIFY_*` error codes were found in the
  firmware in stage 2)
- changing any byte → `BIOS_SIG_FAIL` → the GSP refuses to load
- and the 1.68 GB physical VRAM ceiling will not change through any software operation
