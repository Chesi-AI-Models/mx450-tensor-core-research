# 2026-10-18 · 阶段 3：PRAMIN 通道发现与首次验证

## 一、联网核查（每步一搜的结果）

### 核查 1 · BAR1 为什么全零（真实原因）

> "The GPU's internal page tables only have **~16 MiB of BAR1 mapped (just the display
> framebuffer)**. Reads from the rest return zeros."
> —— nbd-vram 项目分析

**并非 D3cold，而是 GPU 内部页表只映射了 16MB 帧缓冲。** 此前"唤醒 GPU 再读"的假设不成立。

### 核查 2 · P2P 通道对消费级卡关闭

> "`nvidia_p2p_get_pages_persistent`... **the NVIDIA driver returns EINVAL on consumer
> GeForce GPUs**. Both persistent and non-persistent variants, both flag values.
> It's gated at the RM level for Quadro/datacenter SKUs only, regardless of driver version."

### 核查 3 · PRAMIN 通道存在且官方在用

NVIDIA 新的 Rust 驱动 **nova-core** 中：

```rust
const PRAMIN_BASE: usize = 0x700000; // PRAMIN is always at BAR0 + 0x700000
const PRAMIN_SIZE: usize = 0x100000; // 1MB aperture
```

官方文档（[PATCH 09/12] docs: gpu: nova-core）：

```
PRAMIN Window Operation
=======================
1 MiB sliding aperture, repositioned over the entire VRAM address space
using NV_PBUS_BAR0_WINDOW register (0x1700):

 31:26 | 25:24  | 23:0
 RSVD  | TARGET | BASE_ADDR (bits 39:16 of VRAM address)

TARGET: 0x0 = VRAM, 0x1 = SYS_MEM_COH, 0x2 = SYS_MEM_NONCOH

actual_vram_addr = (BASE_ADDR << 16) + pramin_offset
```

本机 `open-gpu-kernel-modules` 头文件同样确认：
`NV_PRAMIN 0x007FFFFF:0x00700000 /* RW--M */`（Maxwell 至 Blackwell 均有）。

## 二、本机实测 1 · 窗口可读

```
[NV_PBUS_BAR0_WINDOW @0x1700] = 0x00007FF0
  TARGET    = 0  (VRAM)
  BASE_ADDR = 0x007FF0
  => 窗口当前覆盖 VRAM 0x007FF00000（2GB 显存末尾）
```

**PRAMIN 机制在本机确认存在，寄存器可读。**

## 三、本机实测 2 · 窗口可写，但读回全零

扫描前 256MB（每 1MB 采样 4KB）：

```
有数据的区域: 0 / 256
WINDOW 已恢复为 0x00007FF0
```

- 写 `0x1700` 无报错（窗口移动成功）
- 但所有窗口读回全零
- 读完后已恢复原窗口值，驱动正常重载

## 四、关键判断：全零是测试条件造成的

**本次测试卸载了 nvidia 驱动**（否则 BAR0 被占用，无法 mmap）。

驱动卸载时 NVIDIA 会清理显存（安全策略），因此整片显存本就为零 ——
这与 PRAMIN 机制是否有效无关。

**同时这也解释了 BAR1 全零的另一层原因**：不只是页表映射只有 16MB，
卸载驱动后显存内容本身也已被清空。

## 五、结论：必须在驱动运行时访问

| 条件 | BAR0 mmap（用户态） | 内核模块 ioremap |
|---|---|---|
| 驱动运行中 | ❌ 被占用，EBUSY | ✅ 可映射 |
| 驱动卸载后 | ✅ 可映射 | ✅ 可映射 |
| 显存内容 | ❌ 已清空 | ✅ 保留 |

**唯一可行路径：写内核模块，在驱动运行时 `ioremap` BAR0 的 0x700000 区域，
用 PRAMIN 窗口读显存。**

## 六、下一步

1. 模块通过 `module_param` 接收 BAR0 物理地址（从 `/sys/bus/pci/devices/*/resource` 读取）
2. 模块内 `ioremap(BAR0 + 0x700000, 0x100000)` 映射 PRAMIN 窗口
3. 另需 `ioremap(BAR0 + 0x1700, 4)` 读写窗口寄存器
4. 保持 nvidia 驱动加载（GPU 有电、显存有内容）
5. 移动窗口扫描显存，寻找 FECS/GPCCS 微码特征

**风险**：与驱动并发访问 BAR0 寄存器可能冲突。需要：
- 只读为主
- 每次读后恢复窗口原值
- 避免在驱动正在操作 PFB/PBUS 时访问
