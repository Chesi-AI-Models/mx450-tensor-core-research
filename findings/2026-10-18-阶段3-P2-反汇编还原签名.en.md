## Reconstructed prototype

```c
void *os_map_kernel_space(void *addr, NvU64 size, NvU32 cache_type)
{
    if (!addr) {
        if (cache_type == 0)
            return <global object>;          /* the global read at 0x...3bd2 */
        ...
    }

    /* mapping is not allowed in interrupt context */
    if (!(read_flags() & IF) || preempt_count())
        return <error path>;

    switch (cache_type) {
    case 0: return map_uncached(addr, size);   /* tail call 0xffffffffb04a4730 */
    case 2: return map_cached(...);
    case 6: return map_xxx(...);
    default:
        log(4, "invalid cache type");
        return NULL;
    }
}
```

**Consistent with the `os_map_kernel_space(virtAddr, size, cache_type)` prototype in the nvidia-open sources.**

## The three known cache_type values at the time

| Value | Presumed meaning | Basis |
|---|---|---|
| 0 | UNCACHED / fast path | `test edx,edx` precedes `cmp $0x2`; zero goes to the tail call |
| 2 | CACHED | explicit `cmp $0x2` branch |
| 6 | WRITE_COMBINED class | `cmp $0x6` branch |
| other | invalid; log and return NULL | default branch |

## Significance

1. **A complete behavioural reconstruction of an NVIDIA kernel function** — not copied from documentation, but read
   out of the machine code
2. the full parameter semantics required to call it were obtained
3. this is the **necessary tool** for P3 ("read the FECS/GPCCS microcode"): reading GPU internal SRAM requires the
   ability to map addresses first

## But this is not the "lock"

`os_map_kernel_space` is **the key that opens the door**, not the lock itself.

- it lets us map a physical address to a kernel-accessible virtual address
- with it, we can read things inside the GPU (VRAM, Falcon SRAM, microcode)
- **the real "lock" is in the FECS/GPCCS microcode and the hardware configuration** (see findings stage 2)
