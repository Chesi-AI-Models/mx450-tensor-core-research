**結論：這是真正的 FECS Falcon 微碼，不是雜訊。**

## 三、成功的關鍵條件（缺一不可）

| 條件 | 為什麼必須 |
|---|---|
| **核心模組 ioremap BAR0** | 使用者態 mmap 會 EBUSY（驅動佔用） |
| **驅動必須載入** | 卸載驅動 → Falcon reset → IMEM 清空（實測全 0） |
| **GPU 必須滿載** | 閒置時 FECS `halted=1`，IMEM 內容不可存取（實測全 0） |
| **FECS 在 LS 模式** | 若為 HS（black box），host 完全不可讀 |
| **IMEMC 位址換算正確** | `(blk<<8) \| (word<<2)`，`blk=addr/256` |

**這五個條件同時滿足，才拿到這 32KB。**

## 四、讀取流程（可重現）

```c
// 1. GPU 滿載（torch 跑 GEMM 迴圈）
// 2. insmod mx450_p4.ko bar0_phys=0x5f000000 mode=dump dump_bytes=32768
// 3. 模組內部：
//    ioremap(BAR0 + 0x409000, 0x1000)
//    讀 HWCFG1 確認 security_model == 2 (LS)
//    儲存 IMEMC(0) 原值
//    for (addr = 0; addr < 32768; addr += 4) {
//        blk  = addr / 256;
//        word = (addr % 256) / 4;
//        writel((blk<<8)|(word<<2), base + 0x180);
//        *(u32*)(buf+addr) = readl(base + 0x184);
//    }
//    還原 IMEMC(0)
//    kernel_write 到檔案
```

## 五、這為什麼是重大突破

**公開資料裡，消費級 GeForce（尤其筆電 MX 系列）上從未有 Turing FECS 微碼被 dump 的記錄。**

原因是一連串「被認為不可能」的限制：

| 限制 | 常規認知 | 本次如何繞過 |
|---|---|---|
| BAR1 只對映 16MB | 讀不到顯示記憶體 | 改走 PRAMIN（BAR0+0x700000） |
| P2P API 對 GeForce EINVAL | 無法 pin VRAM | 不走 P2P |
| 驅動執行時 BAR0 被佔用 | 無法存取暫存器 | 核心模組 ioremap |
| Falcon 若為 HS 則黑箱 | 完全不可讀 | **實測為 LS**（關鍵） |
| 閒置時 Falcon halted | IMEM 不可存取 | **製造 GPU 滿載** |

**五道鎖，逐一打開。**
