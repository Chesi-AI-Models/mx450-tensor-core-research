## 还原的函数原型

```c
void *os_map_kernel_space(void *addr, NvU64 size, NvU32 cache_type)
{
    if (!addr) {
        if (cache_type == 0)
            return <全局对象>;              /* 0x...3bd2 读的全局 */
        ...
    }

    /* 不允许在中断上下文中映射 */
    if (!(read_flags() & IF) || preempt_count())
        return <错误路径>;

    switch (cache_type) {
    case 0: return map_uncached(addr, size);   /* 尾调用 0xffffffffb04a4730 */
    case 2: return map_cached(...);
    case 6: return map_xxx(...);
    default:
        log(4, "invalid cache type");
        return NULL;
    }
}
```

**与 nvidia-open 源码中的 `os_map_kernel_space(virtAddr, size, cache_type)` 原型一致。**

## cache_type 三个已知取值

| 值 | 推测语义 | 依据 |
|---|---|---|
| 0 | UNCACHED / 快速路径 | `cmp $0x2` 前先 `test edx,edx`，等于 0 走尾调用 |
| 2 | CACHED | 显式 `cmp $0x2` 分支 |
| 6 | WRITE_COMBINED 类 | `cmp $0x6` 分支 |
| 其他 | 无效，记录日志返回 NULL | 默认分支 |

## 意义

1. **完整还原了一个 NVIDIA 内核函数的行为**——不是从文档抄，是从机器码读出来的
2. 拿到了调用它所需的全部参数语义
3. 这是 P3「读取 FECS/GPCCS 微码」的**必要工具**：要读 GPU 内部 SRAM，必须先能映射地址

## 但这不是"锁"

`os_map_kernel_space` 是**开门用的钥匙**，不是锁本身。

- 它能让我们把物理地址映射到内核可访问的虚拟地址
- 有了它，才能读 GPU 里的东西（显存、Falcon SRAM、微码）
- **真正的"锁"在 FECS/GPCCS 微码和硬件配置里**（见 findings 阶段2）
