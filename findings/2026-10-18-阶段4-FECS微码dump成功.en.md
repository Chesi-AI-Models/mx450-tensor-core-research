```
gk20a fecs_inst.bin : d0 00 10 00 00 fe 04 00 bd a4 7e 2f 3a 00 f8 02
```

**`00 fe 04 00 bd a4 7e` matches perfectly.** The differences in the third byte (stack top 0x10 vs 0x20) and in
the following addresses are expected (DMEM size and function layout differ between generations).

**Conclusion: this is genuine FECS Falcon microcode, not noise.**

## 3. The conditions for success (all required)

| Condition | Why it is required |
|---|---|
| **kernel module `ioremap` of BAR0** | user-space mmap returns EBUSY (occupied by the driver) |
| **the driver must be loaded** | unload the driver → Falcon reset → IMEM cleared (measured all zeros) |
| **the GPU must be at full load** | when idle FECS has `halted=1` and IMEM contents are inaccessible (measured all zeros) |
| **FECS must be in LS mode** | if HS (black box), the host cannot read it at all |
| **correct IMEMC address arithmetic** | `(blk<<8) \| (word<<2)` with `blk=addr/256` |

**Only when all five hold simultaneously did we obtain these 32 KB.**

## 5. Why this is a major breakthrough

**In public material there is no record of Turing FECS microcode ever being dumped from a consumer GeForce
(especially a laptop MX part).**

The reason is a chain of limitations that were "considered impossible":

| Limitation | Conventional wisdom | How it was bypassed here |
|---|---|---|
| BAR1 maps only 16 MB | VRAM unreadable | go through PRAMIN (BAR0+0x700000) |
| P2P API returns EINVAL on GeForce | cannot pin VRAM | skip P2P |
| BAR0 occupied while the driver runs | registers inaccessible | kernel-module ioremap |
| Falcon is a black box if HS | completely unreadable | **measured as LS** (critical) |
| Falcon halted when idle | IMEM inaccessible | **drive the GPU to full load** |

**Five locks, opened one by one.**
