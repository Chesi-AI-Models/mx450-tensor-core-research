# 🔴🔴 階段 4 · FECS 微碼反組譯成功（11401 行 / 449 條暫存器寫入）

## 一、工具鏈打通

```
apt install cmake flex bison libxml2-dev libpciaccess-dev pkg-config g++
git clone --depth 1 https://github.com/envytools/envytools   (11 MB)
cmake -DDISABLE_HWTEST=ON -DDISABLE_NVA=ON -DDISABLE_VDPOW=ON .
make envydis -j4
```

**踩到的坑**：
1. `CMakeLists.txt` 第一行是 `project()`，第二行才是 `cmake_minimum_required` → 已改為 3.5
2. 只裝了 gcc 沒裝 **g++** → CMake 報「compiler not found」，裝 g++ 後通過
3. envydis 輸出帶 **ANSI 顏色碼**，需加 `-n` 停用，否則正則全不匹配

**最終指令**：
```bash
envydis -m falcon -V fuc6 -i -n fecs_imem.bin > fecs_plain.asm
```

## 二、反組譯結果

**11401 行，1.3 MB**，`-V fuc6` 與 `core_rev=6` 完全對應。

### 入口（0x0）

```asm
00000000: mov $r0 0x2000        ; 堆疊頂端 0x2000
00000005: mov $sp $r0           ; 設定堆疊指標
00000008: clear b32 $r10
0000000a: lcall 0x6ca0          ; 呼叫 main（位於 0x6ca0）
0000000e: exit                  ; 返回即停機
```

**與社群對 AD102 的分析結構完全同構**（AD102: 堆疊頂端 0x2800 → `lcall 0x7747` → 停機），
差異僅來自世代不同（DMEM 大小、函式佈局）。

### main 位於 0x6ca0（第 9115 行）

```asm
00006ca0: f9 52              C  mpush $r5
```

## 四、範例程式碼（寫 0x20600 系列）

```asm
00000076: mov $r9 0x20600          ; 目標暫存器
0000007a: extr $r10 $r14 0x3:0x3   ; 取位元段
0000007d: iowr I[$r9] $r15         ; 寫入
00000080: iowr I[$r9] $r14         ; 再寫
00000083: bra b32 $r10 0x0 ne 0x8c
00000087: mov $r15 0x2
00000089: iowr I[$r9] $r15         ; 條件寫入
0000008c: ret
```

這是典型的「配置暫存器 + 條件分支」模式。
