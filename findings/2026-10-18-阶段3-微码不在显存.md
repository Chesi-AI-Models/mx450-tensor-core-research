# 阶段 3 · 32MB 显存 dump 分析：Falcon 微码不在此处

**简体中文** | [繁體中文](2026-10-18-阶段3-微码不在显存.zh-TW.md) | [English](2026-10-18-阶段3-微码不在显存.en.md)

## 一、分析方法

用 gk20a（Kepler）微码作参考提取特征：

```
fecs_inst.bin : d0 00 10 00 00 fe 04 00 bd a4 7e 2f 3a 00 f8 02
gpccs_inst.bin: d0 00 08 00 00 fe 04 00 bd a4 7e d9 1e 00 f8 02
                    ↑     ↑^^^^^^^^^^^^^^^^^
                栈顶变化   12 字节共同前缀
```

cracker 社区对 AD102（Ada）FECS 的逆向笔记也确认：入口 0x0 是「栈顶 + `lcall main`」，
反汇编用 `envydis -m falcon -V fuc6`。

## 二、扫描结果

| 检测项 | 结果 |
|---|---|
| 强特征 `00 fe 04 00 bd a4 7e`（8 字节） | **0 处** |
| 放宽 `d0 00 ?? 00` | 215 处，但上下文均为数据表（如 `d0 00 d1 00 d2 00 d3 00`） |
| 高熵 4KB 块（非零率 > 80%） | 6457 / 8192 |

**结论：32MB dump 中不存在 Kepler 风格的 Falcon 微码。**

## 三、原因（有明确文献依据）

> "Falcons have **separate instruction and data memories (IMEM/DMEM)** and provide a small
> DMA engine (via the FBIF - 'Frame Buffer Interface') to load code from system memory."
> —— kernel.org `gpu/nova/core/falcon.html`

**Falcon 微码被加载进 Falcon 自己的 IMEM（内部 SRAM），不在 VRAM。**

我们 dump 的 32MB 是 **GSP 的运行时数据区**（含固件副本、堆、表结构），
不是微码存放区。

## 四、读取 IMEM 的障碍

> "**Heavy Secure (HS)**: In this mode, the microprocessor is a **black box** — it's not
> possible to read or write any Falcon internal state or Falcon registers from outside
> the Falcon (for example, from the host system)."
> —— NVIDIA `Falcon-Security` 公开文档

安全模式分级：

| 模式 | 谁能加载 | host 能否读写内部状态 |
|---|---|---|
| NS (PL0) | 不需要签名 | 可以（但能力受限） |
| LS (PL2) | 需 HS ucode 加载 | 部分可见（便于调试） |
| **HS (PL3)** | **需 NVIDIA 签名** | **完全不可见** |

启动链（Ampere/Turing 同构）：

```
硬件 BROM → HS ucode (Booter, 在 SEC2) → LS ucode (GSP-RM, 在 GSP)
```

而 FECS/GPCCS 由 **HS 的 FWSEC / devinit** 加载，很可能运行在 LS 或 HS 模式。
若为 HS，则 IMEM 对 host 完全不可读。

## 五、目前掌握的完整事实链

| # | 事实 | 依据 |
|---|---|---|
| 1 | TC 指令存在，吞吐被压到理论值 5% | SASS + 三路径实测 |
| 2 | GSP 固件是双层 RISC-V ELF，不含 TC 控制逻辑 | 完整反汇编 |
| 3 | Ampere 的 PLM/SS0/SS1 机制在 Turing 固件中不存在 | 8 地址零命中 |
| 4 | vBIOS 受 FWSEC 证书链验证 | 固件内错误码枚举 |
| 5 | **可以在驱动运行时通过 PRAMIN 读写显存** | 写-读回 CHANNEL WORKS |
| 6 | **显存中不含 Falcon 微码** | 本次 32MB dump 分析 |
| 7 | Falcon 微码在 IMEM；HS 模式下 host 不可读 | NVIDIA 公开文档 |

## 六、下一步（唯一剩余方向）

**尝试通过 Falcon 寄存器访问 IMEM**：

1. 在 BAR0 中定位 FECS / GPCCS 的 Falcon 寄存器基址
   （envytools 文档有 Falcon 寄存器布局，但 Turing 的实例偏移需确认）
2. 读 Falcon 的 `CPUCTL` / `HWCFG` 寄存器，判断当前安全模式
3. 若为 NS/LS → 可尝试读 IMEM（通过 `FALCON_IMEMC/IMEMD` 或 `DMEMC/DMEMD`）
4. 若为 HS → 此路不通，只能等 NVIDIA 公开资料或硬件层手段

**前置检查**：读 `NV_PFALCON_..._HWCFG` 的 `SECURITY_MODE` 字段即可判定，成本很低。
