# 2026-10-18 · 阶段 1 补记 3：CUPTI 路线（A 方案）判定为不可用

**简体中文** | [繁體中文](2026-10-18-阶段1-补记3-CUPTI不可用.zh-TW.md) | [English](2026-10-18-阶段1-补记3-CUPTI不可用.en.md)

## 目标

用 CUPTI 枚举 GPU 暴露的性能计数器，查找 `sm__pipe_tensor*` 类指标，
直接观察张量管线是否被物理激活。这比 TC 计数更接近硬件真相。

## 环境

- CUPTI 库：`/vol1/ganlin/venv/lib/python3.11/site-packages/nvidia/cuda_cupti/lib/libcupti.so.12`
- 头文件齐全（`cupti.h` / `cupti_metrics.h` / `cupti_events.h` 等）
- 导出符号确认存在：`cuptiDeviceEnumMetrics` / `cuptiDeviceGetNumMetrics` /
  `cuptiMetricGetIdFromName` / `cuptiMetricEnumEvents`
- 工具：`tools/enum_cupti_metrics.py`（ctypes 直接调 CUPTI，无需编译）

## 尝试 1 · 直接枚举

```
cuInit -> 0
cuDeviceGet -> 0  device = 0
cuCtxCreate -> 0
cuptiDeviceEnumMetrics -> rc = 38
共收集到 0 个 metric
```

CUDA 侧全部初始化正常，**唯独 metric 枚举被拒**。

## 尝试 2 · 开放 profiling 权限后重试

GeForce 默认限制 profiler 权限，遂写入模块参数并重载驱动：

```
/etc/modprobe.d/nvidia-profiling.conf:
  options nvidia NVreg_RestrictProfilingToAdminUsers=0

modprobe -r nvidia_uvm nvidia_drm nvidia_modeset nvidia
modprobe nvidia / nvidia_modeset / nvidia_drm / nvidia_uvm
nvidia-smi -L  ->  GPU 0: NVIDIA GeForce MX450（正常）
```

重跑枚举：

```
cuptiDeviceEnumMetrics -> rc = 38
共收集到 0 个 metric
```

**结论：不是权限问题。**

## 判定

`CUPTI 38` 在本地头文件中无法直接定位到字面枚举（该头文件用条件编译生成）。
排除权限因素后，最可能是：

- 该 CUPTI 版本（12.1.105）不支持对这块 GPU 做 metric 枚举，或
- `cuptiDeviceEnumMetrics` 需要前置的 profiler config 初始化，而该初始化在 GeForce 上不可用

**无论哪一种，A 路线在当前环境下不可用。**

## 三条诊断路线的最终结论

| 路线 | 手段 | 结果 | 卡点性质 |
|---|---|---|---|
| B-1 | `NV2080_CTRL` ioctl 读 TC 计数 | 通道打通（ROOT_CLIENT 成功），GR_GET_INFO status=31 | 驱动对象模型未通 |
| A | CUPTI metric 枚举 | `rc=38`，零 metric（含开放权限后） | 库/权限双重限制 |
| C | 系统 BIOS devinit 分析 | 未开始 | 需 dump BIOS |

**两条高层诊断路径都被封死，但都属于「工具链限制」，不是原理层面的否定。**

## 对核心结论的影响

**无影响。** 以下四条证据互不依赖，任一成立即可支撑「TC 存在但被限速」：

1. `ptxas -arch=sm_75` 对 `mma.m16n8k8` 生成真 HMMA 指令（opcode 指纹与 FFMA 版截然不同）
2. 该指令执行不报错（若 TC 完全缺失应触发非法指令）
3. 吞吐恒 0.60 TFLOPS，**低于纯 FFMA 的 3.06** —— 走的是比软件展开更低效的路径
4. `cuBLAS` 请求 `TENSOR_OP` 算法后 0.32 TFLOPS，比 FP32 慢 6.4 倍

**要再往下走，必须越过用户态：**

1. **写内核模块直接 mmap BAR0** —— CMPUnlocker 走的正是这条路
   （它的补丁直接改 `nvidia-open` 内核模块，绕过所有用户态 API）
2. **dump 系统 BIOS 分析 devinit 表** —— 唯一还没试过的高层路径
3. 物理测量（示波器/功耗计）—— 与本项目目标无关
